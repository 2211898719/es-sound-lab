用户确认文件位于车机“内部存储/carota”，会自动分片。本地分析样本`com.carota.chery.v4[2618T2026-1031-1559-55].log`，40,297,397字节、281,398行，SHA-256：`2edf5f459594c89687b4f587767091f3a94aec6895c073aa35ee4791da80e667`。原文件含VIN、账号、手机号等，不拷入仓库、不随本App导出整文件。

日志覆盖2026-10-31 15:59:55.553～22:44:12.651。11,490条`ConditionHandlerImpl.kt >Vehicle condition data`中，挡位有9次变化：19:20:50.610 R，19:21:00.820 D，19:21:28.483 P，19:41:37.114 D，19:41:46.962 R，19:41:57.224 D，19:42:24.580 P，19:42:41.724 D，19:43:03.149 P。该组记录最后时间19:43:19.978；不能把整个文件最后更新22:44当作车况最后更新。

同文件另有22,995条`OtaVehicleInfo`，其中`GearStatus`全0、`DrivenSpeed`全0，不能替代真实变化的`GearState`。驻车制动`HANDBRAKE_ON/OFF`有6次变化，但不等于AutoHold；车速一直0、锁固定LOCK_OFF、充电固定CHG_OFF，不能据此确认完整动态协议和含义。未发现四门/尾门状态。车况记录正间隔中位约0.61秒，但15次间隔超过5秒、最长1151.47秒；上游持续实时性不能保证。

## 原厂写入器静态核对（2026-11-01）

新提供的`系统升级_1.7.0.2609r.apk`确认包名为`com.carota.chery.v4`，对应Logger每行`println`之后立即`flush`，不像按秒/容量积累后再统一刷出的应用层缓冲。`ConditionHandlerImpl`是在车况查询完成后才记整组快照，挡位getter读取该快照；查询频率/上游响应或缓存可能影响实时性，尚未完成车端定位。详见[系统升级APK分析](carota-logger-apk-investigation-20261101.md)。

日志源时间是查询结束后的日志生成时间，不是实车信号时间；因此日志年龄小也不能证明状态没有上游延迟。文件头的`@目录/进程名`是目录与文件名前缀拼接，不能单凭该行证明包名子目录存在；当前兼容两个位置的选择逻辑保持不变。

## 范围及选择

入口：“车辆检测 → 来源 → Carota → 确认读取”。保留现有来源设置，不自动从旧文件或logcat切换。

仅扫描当前用户主共享存储目录（通常`/storage/emulated/0`）下`carota`及其精确子目录`com.carota.chery.v4`。依据样本文件头记录的包名子目录，同时兼容用户将.log直接放在carota根目录的布局。不递归全盘、不进入其他应用私有目录、不搜索U盘或解压归档。

只匹配`com.carota.chery.v4[数字Tyyyy-MMdd-HHmm-ss].log`，严格校验日期、普通文件和符号链接，忽略其他包/压缩包/无效名称。两层目录合计条目上限4096，超过则停止并显示错误。按文件名时间选最新，不因为旧文件mtime被触碰就回退旧分片；同时间候选初选以mtime和路径稳定决胜，已选文件仍在时不在同秒候选间来回跳转。

监听期间每250ms检查。出现时间更晚的分片即切换；当前inode变化也重建基线。只有旧分片被删且尚无更新分片时，等待而不回退更早文件。空目录或短暂文件ENOENT进入`waiting-shard`，自动等待后续文件；目录缺失、拒绝读取、超过条目上限等真实错误停止，需用户重连。不自动创建目录、不改权限、不删除或清理原厂日志。

## 增量与时效

复用原有有界文件读取：启动/重连/轮转/截断/边界改写/过大积压均从EOF等待后续新行，舍弃已有历史和跨连接半行；单行8192字节、单轮64KiB、积压阈值256KiB，UTF-8完整行解析，未读归档不补播。

只接收`[INFO] yyyy-MM-dd HH:mm:ss.SSS in ConditionHandlerImpl.kt(行号) >Vehicle condition data: ...`。从`GearState`得到PARKING→P、REVERSE→R、DRIVE→D；N/M未实证不猜测。缺字段、重复字段或未知命名形成无效挡位，清除旧有效基线。内部样本主题为`Carota/VehicleCondition/GearState`，属性ID为0的内部身份，不冒充厂商数值属性ID。统一样本的status=0是App接受该日志结构的标记，不是Carota提供的硬件状态字段；UI明确显示“命名字段”，不冒充读取过厂商status。

日志源时间按设备本地时区严格解析，不用收到时间替代；时间须在本次文件基线之后、当前近5秒内、至多超前500ms，接收及主线程都检查；重复/倒序/旧队列丢弃。轮转、恢复、校准保存/结束后的首样本静默，不补播历史。已开启挡位短提示组时，后续有效变化可进入原有短音链；本版仍不自动启动倒车/行人/声浪持续循环。测试前关闭音效组，先核对显示与实车操作。

## 权限、导出及边界

新增Manifest普通运行时`READ_EXTERNAL_STORAGE`；仅用户确认选择Carota时请求，不请求`READ_LOGS`、所有文件管理、ADB、root、工程开关或服务接口。拒绝授权不切换来源；实际读取仍受本车存储策略/SELinux限制，已授权不代表文件一定可读。来源已选但读失败可检查应用权限，再重新选择或重连。文件管理器能看到不等于本App有权限。

页面显示当前分片名、新增字节、相关车况行、错误及更新提示；“更多 → 读取详情”和JSON`fileLog.path/backend/metadata/rotations/phase`记录实际文件，`eventBackend=carota`仅表示选择，不代表成功。只将车况行交给现有有界诊断，不采集Carota账号/VIN/网络等其他行，更不导出整份原始文件。历史诊断仍保留原schemaVersion 2。
