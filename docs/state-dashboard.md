# 车辆状态大屏与统一校准（0.3.21）

## ICC来源

“来源 → ICC车况”在同一快照显示挡位、手刹/EPB、电源、充电、中控锁和车速原始值。首样本不播报，缺失明确标记“字段缺失”，未知值保留原值；最近回复不是车辆传感器时间，不能保证当前。手刹不是AutoHold，电源不推断可行驶，车速单位未确认，均只读展示。

点击中控锁/充电卡片可分别核对并确认本来源触发，默认不确认、不启用音效组；锁不继承旧日志校准，仍需另行确认车外输出。充电1/2为非充电、3/4为充电，只在两类之间变化触发，不能解释为插拔枪检测。日志预设不改写ICC协议。详见[ICC车况来源](icc-trigger-source.md)。

## Carota来源

0.3.17可在“来源”中确认选择Carota最新分片，详见[目录与权限说明](carota-file-route.md)。当前仅接入已观测变化的`GearState=PARKING/REVERSE/DRIVE`，原值显示英文命名、来源显示Carota文件；不把一直为0的`OtaVehicleInfo.GearStatus`作为挡位。车速、门、锁和AutoHold未接入，不以其他相似字段冒充。其余卡片保留“未收到/待新样本”，充电继续标记“未接入”。

Carota命名挡位不套用ES数字预设或绑定MessageProperty的手动数值映射；点击挡位卡片解释当前命名和已验证范围，不能将未知N/M通过数字校准制造出来。数字预设及其他来源的既有校准仍保存，换回对应来源才适用。校准静默、新鲜度及待新样本保护保持不变。

## 显示范围

入口：“车辆检测 → 全屏显示”。大屏保留原10张卡片（挡位、车速、四门、后尾门、中控锁、AutoHold、充电），新增手刹/EPB和电源，共12张。新增两项只读，不出现在统一数值校准列表；ICC充电使用本来源独立确认，其他来源仍标记未接入。门、尾门、AutoHold未由ICC接入，不因相似字段推测。倒车、行人和声浪的持续循环音仍暂停自动接入；喊话是手动功能，不伪装成车况。

每张已支持卡片显示解析状态、原始值、status、来源、收到时间、收到次数和原值变化次数。原值变化次数不是实车操作次数或播放次数。没有样本显示“未收到”，断开或重建基线显示“待新样本”；无效status、未知枚举、未校准锁/AutoHold分别明确提示，不默认填充P挡或关闭。

近5秒有效样本才以绿色显示，接收时间和日志源时间均检查，最多容忍500ms超前；旧值显示灰色“上次状态”，不是持续实时保证。日志生成时间不等于车辆传感器时间，即使日志持续更新也需核实上游是否提供缓存值。文件打开成功、收到次数增长或校准成功，都不能证明实际车辆状态已经读通。

宽屏4列、中屏3列、窄屏2列。窄屏及大字号可滚动，不能以截图是否一屏容纳代替所有分辨率验证。全屏隐藏顶部导航和近期日志，保留来源、错误和监听控制；前台保持常亮，返回键或“退出大屏”恢复普通视图。退到后台解除常亮。

## 可选ES预设

入口：“车辆检测 → 统一校准 → ES已知预设”。默认不自动应用；可以先查看已知值，勾选希望应用的项目，再点击“应用所选预设”。无需收到样本即可选择配置，但没有实际日志时大屏仍显示“未收到”，不创建假数据。

- 挡位：主日志`DrivingInfo/Gear`已知P=1/101、R=2/102、N=3/103/300、D=4/113；AVM别名仅1～4。M挡含义未确认，不把5当作M。
- 四门/尾门：原始0=关闭、1=打开，同时保留当前解码器的已知`color`判定，不能简单把所有门日志只按raw判定。主驾只用原值；副驾/后门附带有限数字color时2表示打开、其他数字表示关闭；尾门color=2打开、0/1关闭，其他无效。两种已知尾门topic均保留。
- 车速：沿用现有`DrivingInfo/Speed`日志km/h解析，单位仍需实车核对；用户确认实际为m/s时使用单项手动单位校准，不在预设中猜测新比例。
- 中控锁、AutoHold、充电不纳入。锁0/1、AutoHold1/2虽有观测，但缺少语义确认，不因应用ES预设变成已校准。

ES预设是命名保存的现有ES日志解析，不是新的读取接口或实车认证。仅覆盖勾选项的本地手动映射，未勾选项的手动校准保留；原有ES预设取消勾选则恢复默认解析。卡片标记“ES预设 · 待核对”，JSON记录`preset=es-known-log-v1`和`verifiedOnVehicle=false`，不谎称已经实车确认。

应用、重选和移除都会清除受影响状态的基线与旧队列；校准模式内不会自动播音，完成后新鲜首样本仍静默。选择预设不改变日志身份、来源、权限、音源、组开关或车外输出确认。有效性、时间和已知身份检查仍由现有解析/监听链路处理，保留别名优先级与无效值保护。

“移除ES预设”只移除仍标记为ES预设的项目，恢复原默认解析，不删除后来保存的手动校准。预设项收到真实样本后可继续单项校准，表单预填已知简单值，必须实车确认才能保存；保存后变为绑定该实际日志身份的手动映射，不再套用该项ES预设。若需保留color/多原值别名判定，不应未经确认改存简单手动映射。

## 校准流程

1. 关闭自动音效组。仅在安全驻车、全程踩住制动、周围无人的条件下按车辆允许的操作对照状态；无需行驶，不为了车速校准开车。
2. 开始监听，确认有该项实际日志。“未收到”无法通过填写数字创造状态；文件权限拒绝需先解决读取问题，校准不能替代权限。
3. 点击“统一校准”选择状态，或直接点卡片。校准模式停止当前音频和麦克风，暂停自动音效，但继续采集状态。
4. 挡位填写P/R/N/D对应的原始非负整数，M可留空；门/尾门填写关闭、打开原始整数。不同语义不能重复使用同一个值，不能填写小数、负数或超出32位非负整数范围的值。
5. 可在确认实车当前含义后点该行“取当前”，仅接受同topic/ID/area/来源、近5秒、status=0的有效数字。没有新样本则明确拒绝，不把旧状态当作新采样。手填只填写已经观察并确认的数值。
6. 车速只选择原始单位km/h或m/s，m/s按3.6换算；输出仅允许有限的0～300km/h。不估计比例、油门、转速，也不启动持续音。
7. 勾选“已对照实车确认上述含义”，保存。可以继续其他卡片，最后点“完成校准”；下一份新样本只建立静默基线，不补播校准期间变化。校准不自动打开音效组。

通用校准绑定当前实际已观测的日志身份（来源、topic、属性ID、area），仅改变App本地解析映射，不写入车辆。映射持久保存；同身份未包含的原始值标记未映射，不回落默认；其他来源/别名不套用该映射。表单展示绑定身份及开窗时原始值，并明确可能已旧；旧样本可作为手动确认参考，但不能用“取当前”伪装为新样本。

“恢复默认”只清除此项自定义映射并使旧播放队列失效，不能删除日志，也不重置其他状态、音源、权限或车辆。锁/AutoHold沿用既有校准对话框；中控锁仍需单独确认车外输出设备，校准不能替代实际外放验证。

校准模式只在检测页前台维持。切换其他页面、返回退出检测页或退到后台会结束校准；退到后台时关闭未保存表单，不会自动保存。正常已启动监听继续。重新进入需要重新点击校准，不会悄悄保持静默。

## 导出与验证边界

“导出记录”增加`stateCalibrations`（自定义身份和映射）、`currentStates`（原始/解析值、status、身份、源/接收时间、计数及live证据）、`calibrating`，保留schemaVersion 2与旧字段。清空诊断记录不清除持久校准。

本地自动测试覆盖静默校准、完成后的首样本基线、旧队列取消、身份隔离、无效/未知值、枚举输入校验、车速单位、过期采样拒绝、后台表单取消、全屏退出及横竖屏布局。**没有连接实车验证文件权限、实时状态、功放或后台可用性**。车端仍固定P挡时，应导出原始日志检查数据源，而不是靠校准制造挡位变化。
