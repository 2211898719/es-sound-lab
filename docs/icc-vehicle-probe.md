# ICC只读车况检测（0.3.19）

> 此文说明“更多”菜单中的独立限时探针，不接入音效。0.3.20新增的持续查询/音效模式见[ICC正式挡位触发来源](icc-trigger-source.md)，两者不会同时轮询。0.3.19后续实车JSON已确认30次有效回复及4次P/D变化，不再将该样本描述为目标尚未验证可达；正式来源的新版本播放与稳定性仍待实测。

## 0.3.19 Seed兼容修复

用户报告`failed response seed mismatch`，复核原厂`j2.f.c()`后确认：请求Seed只用于请求加密，响应读取自己头部的Seed独立派生解密密钥，原厂不要求二者相同。0.3.18错误增加了相等校验，0.3.19移除这一误判；不是关闭服务鉴权，也不增加任何接口或权限。

请求仍生成20位小写字母；响应不套用请求生成格式，保留头值原样用于UTF-8密钥派生，不裁剪空格或改写大小写。App的防御性边界为1–256个可打印ASCII字符，拒绝空值、超长及控制字符；这是本App的边界，不是已经确认的服务端最大长度。加密类型缺Seed、密文损坏或解密失败仍停止，不回退为明文，不记录真实Seed或密钥。

本地回归覆盖独立响应Seed、大小写/数字/分隔符、边界及非法头值，并用仅本机回环HTTP代理返回与请求不同的Seed。原厂信封独立OpenSSL向量保持不变。用户此前的错误只能说明处理到带Seed的200响应；不能证明已成功解密、有效车况或实时挡位，仍需新版本实车导出。

## 目的与入口

在“车辆检测 → 更多 → ICC 只读车况检测”打开面板，阅读驻车提示后手动点击“开始限时检测”。打开面板、应用启动、开机恢复和选择Carota日志均不会自动发起ICC请求。

本功能验证从原厂系统升级APK找到的ICC车况查询路线，不是执行车控：不挂挡、解闭锁、调车窗、切电源、启动升级、修改鉴权或注册未知回调。不会把ICC快照送入音效、状态校准或现有日志事件链。原有日志来源不改变，可同时对照日志读取；本功能开始时停止旧的原生接口探针。

## 证据与请求白名单

源APK：`com.carota.chery.v4` / `1.7.0.2609r`，SHA-256：`0397699703f9218ba3e8a183cd329d4572df53bb2db2058d6af133665133b2b8`。静态链路和限制见[原厂APK分析](carota-logger-apk-investigation-20261101.md)。

- 固定HTTP代理：`192.168.55.31:51020`，来自原厂`cfg_rpc`配置，不扫描端口或地址，不允许输入任意URL。
- 固定逻辑服务和路径：`ota_icc_vsi`的`/cdt`，对应`vsm.subde → vsi_de_condition → ota_icc_vsi`。
- 固定HTTP方法POST；请求体仅为`Telemetry.EmptyReq(tag=MDA)`。POST在这里是原厂只读查询的传输方法，不代表调用状态变更操作。
- 对齐原厂`cs/pb-a`信封，使用每次新的20字符seed和APK内的固定格式参数进行HmacMD5派生及AES/CBC处理。不把seed、格式参数、原始请求/响应体或协议密钥写入诊断。
- 不请求`/event`、`/sys`、`/info`、升级、复位、电源、日志上传/清理等路径；不启动原厂Activity/服务，也不模拟平台签名。
- 不跟随HTTP重定向、不探测备用服务、不在401/403后绕过鉴权。固定私网地址和逻辑服务是静态候选，不是已经验证存在或普通App一定可达的保证。
- Manifest只为固定逻辑域名及代理IP配置窄范围明文传输例外，不对所有目标开放明文访问；没有新增权限。此格式匹配不是TLS安全性或车辆信号真实性的认证。

即使查询没有改变车辆状态的指令，上游仍可能因查询产生负载或新增原厂日志；因此不做无限轮询。

## 有界生命周期

- 后台单线程、串行查询，上一次结束后至少等待1秒；最多30次或60秒，以先到者为准。
- 连接/读取超时各1500ms，另有3500ms定时断开和读取阶段总时限检查；响应最多32768字节。系统底层调度可能影响实际结束时间，不能把配置值当成精确实车时延上限。
- 网络、权限、非200 HTTP或结构错误明确停止，不自动重试。有效HTTP回复但没有已知挡位会显示“缺失/未知”，仍可在本次上限内继续对照。
- “停止检测”“停止并关闭”、取消弹窗、离开检测页、进入后台、导出、清空记录、停止监听或服务销毁均取消本轮请求，并关闭当前连接、移除定时任务。旧回调不能覆盖停止后的报告。
- 进程恢复只加载历史报告；上次活动会话标记`previous-session-interrupted`，不恢复ICC网络请求。

## 解析、显示和导出

只解析`VehicleConditionRsp`的6个数值字段：`speedRaw`（2）、`handbrakeRaw`（6）、`powerRaw`（7）、`chargingRaw`（8）、`gearRaw`（9）、`lockRaw`（13）。不保存trace、VIN、账号或其他未知字段；不根据这些原始值推测AutoHold、门状态、单位或实车权限。

挡位枚举按该APK的protobuf定义独立显示：1=P、2=N、3=D、4=R；0/其他值显示未知，字段缺失显示缺失，不默认补P、不套用MessageProperty数字或Carota日志命名预设。N只说明APK协议定义，尚未实车确认。重复字段、错误wire类型、截断、溢出及超限响应拒绝使用。

界面区分请求次数、HTTP 200次数、已知挡位快照数和变化次数，并显示查询耗时、最近挡位及回复时间。第一条有效挡位只建立比较基线；缺失/未知后清除基线，不将恢复当作确定变化。主线程排队超过5秒的旧回复不进入快照。

**回复时间不是信号产生时间。** 原厂响应没有在本功能中验证可用的车辆源时间，报告显式标记`upstreamTimestampAvailable=false`。一次200或解析成功、一直P或0次变化，都不能独立证明实时性或证明服务未实现。即使面板还在检测，最近快照也标注“不保证当前”，停止后仍以历史回复显示。

“导出记录”先停止ICC请求，再按原方式保存检测JSON，增加`iccVehicleProbe`对象：固定目标、源APK版本、App UID、会话、次数、阶段、HTTP状态、耗时、最多30个白名单快照及变化数；不导出原始二进制、网络错误正文或内部格式参数。最新有界报告保存在App私有偏好中，清空检测记录时一并清除。

## 同版Carota时延观测

保留上一轮已编译但未发布的时延观测，并补齐回归：`carotaTiming`记录日志生成到读取的年龄、读取时过期/超前/基线前行数，以及主线程排队与过期数；`fileLog`增加非空读取批次数、最近新增字节/车况行和两次读取的间隔。轮转或重建基线清除最近批次和增长时间，累计次数保留。

这些是读取侧观测，不等同于写入器flush批次，也不包含上游采样/查询延迟。现有5秒时效保护、EOF基线、首样本静默和历史不补播保持不变；不能通过接收旧日志假装改善实时性。

## 车端对照

1. 保留原签名覆盖安装0.3.19，不卸载旧版。可先关闭自动音效组，ICC检测本身不会触发音效。
2. 只在安全驻车、持续踩住制动、周围无人的条件下测试，无需行驶。打开ICC面板并手动开始。
3. 核对HTTP状态和快照，对照车辆允许的挡位操作与面板变化；显示P不等于已证明车在P，0次也不要直接判断接口未实现。
4. 无论超时、拒绝、缺失、固定值或有变化，都用面板的“导出记录”保存JSON。先分析本次真实错误，不先改权限、root或工程开关。

本地验证采用模拟传输、独立OpenSSL信封向量及仅本机回环HTTP代理，不连接真实车机。模拟截图有明确标记，不能当作ICC已可达、真实挂挡变化或低延迟的证明。测试与签名安装包记录见项目交接文档。
