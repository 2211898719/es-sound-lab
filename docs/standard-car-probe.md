# 标准 Android Car 挡位独立检测（0.3.11）

## 本次验证什么

此前提供的 `ES-ADB诊断-20261031-174857.json` 中，`car-service-dump` 列出了
`GEAR_SELECTION (0x11400400)` 和 `CURRENT_GEAR (0x11400401)`，包权限清单显示本App获得
`android.car.permission.CAR_POWERTRAIN`。这仅构成值得验证的线索，不证明普通App能读到新鲜、真实的车辆挡位。

本版新增独立、显式启动的标准Car探针；不恢复旧自动回退链，也不接入音效。
不重试已被拒绝的Mega属性或IMessageCenter，不要求再次提取APK。

0.3.10的实车报告`ES-检测-20261031-192247.json`已证实原App UID能注册、读取并收到两项属性的初始回调，
但都固定为4/P，读取和回调源时间戳相同，报告计算的源龄约16小时11分钟。
该报告保留的最后一轮是2026-10-31 19:22:35.922—19:22:45.114，仅9.192秒，没有后续回调或变化，
没有操作标记。不能由此认定所有操作发生在该窗口内，也不能把这次初始回调当作实车实时状态已打通。

0.3.11新增每轮结束后约1秒的定时读取，保留原回调，两路结果独立统计并实时展示，
用于区分“读会变但通知不来”和“读与通知都不变”，不是自动接入音效的后备链路。

## 实车步骤

1. 用原签名的 `dist/es-sound-lab-0.3.11-debug.apk` 覆盖安装，不卸载旧版，以免丢失设置和私有音频。
2. 进入 **车辆检测 → 标准 Car 挡位 · 独立只读检测 → 开始标准Car挡位检测**，确认提示。
   无需开启扩展检测、日志辅助、音效监听或ADB连接；只用本次新入口。
3. 保持该页面在前台，确认新面板显示“检测中”、倒计时和持续增加的读取次数。
   看“读取”和“回调”的原值/解释及各自的变化次数；不要把下方旧的全局车辆状态当作本探针输出。
   只在车辆安全驻停、周围无人、全程踩住制动且车辆允许的条件下，
   分别选择P/R/N/D，停留数秒；顺序不作要求，无需行驶，不安全就不测试。
4. 可选在“标记当前操作”中选择对应的 **实车挡位 P/R/N/D**，记录刚完成的操作，便于对照时间线。
   不标记不影响读取和回调；应确保操作位于页面显示的本轮检测期间。
   这些标记只写诊断记录，不控制车辆，不把用户选择当作接口数据。
5. 大约60秒自动结束，也可点停止；等清理返回后点“导出记录”，把 **ES-检测-….json** 发回。
   即使原值始终0、没有变化、无回调、缺类、权限拒绝或报错，也应导出。退出本页、应用转后台或导出会停止探针。

## 记录与判读

- 分别保存两项属性的注册返回、当前订阅标记、读取尝试/成功/失败/定时读取次数、读取原值变化次数、
  回调次数、有效回调状态变化次数、源时间戳推进次数、逐项错误。人工停止、离页、后台和导出分别记录停止原因。
- 页面每秒更新，醒目显示“读取值 / 回调值”、两路变化次数、已运行时长及剩余时间；
  详情保留最近收到时间、状态及源时间戳和源龄。读取失败仍显示上次成功值，但明确提示为旧值。
- `lastRead` 与 `lastCallback` 分开，避免缓存读取覆盖最新回调。原始值、值类型、区域、状态、
  源时间戳(ns)、收到时的elapsedRealtime(ns)、墙钟时间和源时间差(ms)均保留。
- 代码的标准挡位解释为1=N、2=R、4=P、8=D、16及以上单比特值为具体前进挡；
  不沿用Mega的1=P、2=R、3=N、4=D编码。原值始终保留，需用实车标记核对，不能只看解释标签。
- `GEAR_SELECTION` 与 `CURRENT_GEAR` 独立统计，不要求二者相等；选定挡位与具体实际挡位不是同一语义。
- 初次回调仅建立基线；原值0/未知、非整数、非全局区域、不可用/错误状态、缺失/未来时间戳、
  重复或逆序时间戳不累加变化，并清除连续变化基线。错误回调也清除基线。读取不建立回调变化基线。
- 读取以可识别整数、AVAILABLE及全局区域建立独立基线；读取失败或无效值会清除该基线。
  `readChanges`只表示两次有效格式读取的原值不同，不要求源时间推进，也不表示实车状态已验证。
  `readTimestampAdvances`及`readChangesWithoutTimestampAdvance`辅助区分源时间推进和“原值变、源时间不变”，
  不将轮询的接收时间更新伪装成源更新时间更新。回调的`changes`仍独立使用严格时间序检查。
- “有效”仅为本地格式、状态与时间序检查，不代表已证实数据来自真实车辆或足够新鲜。
  时间差用于辅助识别旧缓存，不自动认定为实车更新。注册成功、固定0、有时间戳都不能判定路线打通。
- 导出根字段为 `standardCarProbe`；检测JSON及ADB诊断JSON均包含独立快照。
  最近256条结构化读取/回调样本、120条事件有界保留，队列最多64个回调，超量计数报告。
  一轮无大量回调的60秒测试可完整保留约120次读取；超量时只保留最近样本并标记丢弃数量。
  实车标记位于检测JSON原有的标记记录中，不混入回调样本。

## 接口边界与清理

- 运行时反射调用公开形状的 `android.car.Car`、生命周期监听器及CarPropertyManager。
  已对照本地Android SDK35的`optional/android.car.jar`核对这些公开签名、两项属性ID与挡位常量；
  车机自身的库和服务仍以运行时结果为准，不能由编译SDK推定兼容。
  通过 `createCar(Context, Handler, long, CarServiceLifecycleListener)`、等待参数0建立异步连接，
  取得`property`管理器；两项属性分别调用`registerCallback(callback, id, 0f)`和
  `getProperty(Integer.class, id, 0)`。0.3.11起在初次读取后按约1秒间隔继续读取，
  每轮完成后才排下一轮，注册仍只执行一次；不调用任何set/control接口。
- 车机的类、方法或服务缺失，连接失败、读/订阅拒绝均按原异常记录；不做隐藏API豁免、不加载其他APK、
  不冒充系统身份、不改设置/权限/SELinux、不启动工程模式。
  可选的`uses-library android.car required=false`及CAR_POWERTRAIN权限原先已声明，本次未扩大权限。
- 同步远程调用放在单一后台执行器。单阶段8秒、从开始起总计60秒；超时只能停止本地会话，
  不能强行中断已经派发的Binder调用。全局执行租约直到清理返回才释放，阻止叠加会话和无限堆积线程。
  定时读取同样使用该执行器，最多一轮待执行/进行中，不并发、不补发积压轮次；阶段超时仍有效，
  每轮读取不会延长总会话期限。权限拒绝、缺类/方法等静态失败会停用相应属性的本轮轮询，
  其他属性及回调继续保留；暂态读取异常记录失败计数后下一轮再读。
- 对尝试过注册的属性，即使返回false或抛错，也尽力逐项注销；随后始终尝试disconnect。
  迟到回调不再入账；迟到错误可留在报告中。`cleanupConfirmed`只表示本地API清理调用均正常返回，
  不是远端硬件状态的独立证明。未返回时明确标记`cleanupPending`；App进程被结束后标记`cleanupUnknown`。
- 诊断快照单独持久化，旧会话的迟到清理不覆盖新会话报告。
  本地Robolectric测试使用测试专用android.car模拟类，不代表真车服务已验证；这些类不能打进APK。
