# 文件日志路线（0.3.17）

## 最新实车线索

2026-11-01用户确认本车没有`/log/android/logcat.log`，但内部存储`carota`下有自动分片的`com.carota.chery.v4[2618T2026-1031-1559-55].log`。该文件中`Vehicle condition data`实际记录了9次P/R/D变化；这修正此前只有静态路径依据的判断。0.3.17新增可选Carota来源，按文件名时间跟随最新分片，详见[Carota文件路线](carota-file-route.md)。旧固定路径来源保留作对照，不再是本车推荐入口，用户原有来源设置不自动切换。

Carota需要用户主动确认的普通存储读取权限，不是READ_LOGS；能从文件管理器拿到文件不证明本App已获读权限。当前只解析已验证P/R/D，未确认状态不通过数字预设猜测。首次及轮转切换从EOF建立基线，历史只可离线分析，不可回放成当前事件。

## 当前检测页

读取详情、操作标记、权限说明、ADB诊断/APK提取与清空记录在“更多”。清空需二次确认。候选及完整有界证据仍采集、导出，但不再展示无效的候选绑定入口；锁/AutoHold校准可从大屏或首页进入。此次增加明确确认的本地映射校准，不改变日志来源、权限或已有音源；校准期间静默，结束等待新样本重建基线，不补播校准中的变化。

0.3.15在“统一校准 → ES已知预设”中列出已知值，可勾选应用挡位、车速、四门和尾门，保留原解码中的别名及color判定。未确认的锁/AutoHold含义与充电不纳入；默认不应用、不制造样本。配置只改变App解析，文件读取、时效检查和权限边界不变，详见[预设说明](state-dashboard.md#可选es预设)。

## 本次改动

车辆检测页撤下标准Car定时挡位、消息总线、讯飞挡位和Mega原生订阅四块探针；正常监听也不再连接这些接口。旧探针实现和历史JSON字段保留，便于回看证据，不再让用户重复跑已失败的路径。ADB诊断及通用APK提取收进高级入口。音源、组开关、音量、校准、输出设备和旧规则不删除。

首页监听开关和检测页“开始监听”控制同一前台服务。离开检测页不停止正常日志监听；点停止监听、通知停止按钮或结束服务才关闭文件/进程。检测页启动使用started foreground service，不只依赖Activity绑定。

## 日志来源

默认 `file`：App原UID以只读、非阻塞、不跟随最终符号链接的方式打开固定路径 `/log/android/logcat.log`，核对它是普通文件，记录 `/log`、`/log/android`、目标文件的lstat结果和打开错误。没有目录扫描、写入、chmod、grant、setprop、root、挂载或原厂日志服务调用，不自动连接ADB。

该路径来自Owl收集链的离线代码证据，**尚未通过本版在车上验证普通App可读、文件持续写入且含有效车况**。系统UID的Owl能读取不代表本App能读取。文件模式不调用logcat、不申请READ_LOGS，但仍受文件权限和SELinux约束。

- `ENOENT`：本次路径不存在；不误报成权限拒绝。
- `EACCES` / `EPERM`：保留实际失败操作和错误；不尝试修改权限。
- 符号链接、目录或打开期间身份变化：拒绝使用，不把内容当普通日志。
- 打开成功但0新增字节：仅证明可打开，不能证明有实时车况。
- 新增字节增加但有效样本0：可能没有相关事件、时间格式不同、已过期或协议未映射；相关原文及拒绝原因随报告导出。

可在“日志来源”**手动确认**切换到 `logcat`。它使用App UID的READ_LOGS及系统批准，不是ADB shell；Android可能弹出授权确认，断开后不自动反复拉起请求。文件失败不会自动切换。所选来源持久化，恢复监听沿用用户选择。此入口不自动授予READ_LOGS。

## 增量与播放边界

- 每250ms检查固定文件，从打开时的EOF开始；原有内容不读取为事件，旧半行的后半段也不作为新行。
- 保留完整行前的UTF-8字节，不在多字节字符中途解码。单行8192字节、单轮读取64KiB、积压阈值256KiB；过长行或过大积压丢弃并重建基线，防止补播。
- inode/device变化重新打开，从新文件EOF等待；变短或已读边界64字节变化时重新建立EOF基线。不会扫描轮转归档。边界检测不能证明捕获所有同inode覆盖写入；仍需真实写入器行为验证。
- 支持epoch和常见threadtime `MM-dd HH:mm:ss.SSS`，以及含年份的threadtime；按设备本地时区解析，年末跨年取最近年，非法时间拒绝。其他格式不以“收到时间”冒充日志源时间。
- 日志时间须不早于本次打开/重建基线，接收和主线程处理时均不超过5秒，最多容忍500ms超前。同信号重复/乱序时间戳不更新状态。主线程队列128条，溢出使旧队列失效并静默重建基线。
- 只有已知topic+property ID映射进入内置事件；第一次读到、重连、轮转、无效恢复均只建立基线，之后有效变化才触发。挡位拒绝小数及非全局area；DrivingInfo主挡位优先于AVM别名，避免交替来源不断冲掉基线。
- 门、尾门、挡位短提示可用；锁和AutoHold仍须现有校准，锁仍要求单独确认车外设备。不猜未知枚举、不恢复历史自定义日志规则。
- **本版不由日志自动启动倒车、行人或声浪等持续循环音**，避免稀疏日志/文件停止更新后维持旧状态播放。试听与手动喊话保留。充电等未确认协议暂不自动触发。

正常安静间隔不代表断线；上次状态在页面显示“几秒前收到”，不能把旧显示当作当前实车真值。真实读取错误则关闭文件、清除来源基线，等待用户重新连接，不自动重试打开或改走其他身份。

新鲜度是日志行的生成时间，不是车辆传感器时间；即使有新日志，也仍须对照实车判断上游是否输出旧缓存。不能用文件增长或有效解析计数代替物理状态变化验证。

## 车端验证

1. 覆盖安装0.3.15，不卸载旧版；先关闭自动音效组，进入车辆检测，确认来源为文件。
2. 点击“开始监听”，先看错误或新增字节；详细证据在“更多 → 读取详情”。无须授予READ_LOGS、启用工程开关或连接ADB。
3. 文件有新增后，在安全驻车、全程踩住制动、周围无人的条件下，按车辆允许的操作对照挡位或门状态，无需行驶；标记可选。
4. 进入“全屏显示 → 统一校准”，对照卡片原始值及收到时间确认映射，完成后点击“完成校准”。在“更多 → 读取详情”核对相关行和有效新鲜样本，候选完整信息随导出保存。初始样本静默；确认映射后再启用相应短提示组测试。一直P挡或没有变化时，校准不能创造未到达的数据。
5. 成功、固定P、0次或报错都导出JSON。文件不存在/拒绝时先分析实际错误；如果决定接受系统日志授权，再手动选择logcat。不预先宣称“免授权成功”。

导出保留schemaVersion 2和历史探针字段，增加 `fileLog`（UID、实际错误、metadata、打开尝试/成功、phase、字节/相关行、轮转/跳过次数及最近增长时间）、`acceptedLogSamples`、`rejectedLogSamples`；`eventBackend`是用户选定的`file`或`logcat`，不是已经验证能读取的证明。文件证据每5秒及阶段变化持久化，进程恢复后上次运行标记中断；有效/拒绝计数仅为本进程全部日志来源累计。

本地测试覆盖EOF、半行/UTF-8、轮转/截断/同inode改写、积压/超长行、准确errno、不重试、关闭与历史恢复、时效二次检查、静默基线、别名优先级、旧规则不复活、队列上限及来源确认。模拟测试不能代替车端文件权限、原厂写入格式、时延、后台存活和实际音频输出验证。
