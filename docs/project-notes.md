## 已实现的安全播放链路

1. 只识别主题、属性 ID 和区域均匹配的中控锁样本，保留非负整数原始枚举。
2. 用户填写两个不同的闭锁/解锁实际值；空配置、未知值、无效状态不猜测事件。
3. 首样本、来源恢复、重连和校准后的首个有效状态仅建立基线；重复值不重复播音。
4. 解闭锁不走通用规则，避免普通事件绑定绕过专用车外路由。
5. 普通输出 `output` 与 `lock.output.*` 分开。锁设备 ID、类型、名称和地址必须匹配；重新选择设备需要重新确认。唤醒后设备 ID 是否变化仍需观察，当前不会自动按名称迁移。
6. 显式试听允许未人工确认的已选设备；自动播放必须人工确认。无设备、拒绝路由、路由不符或设备消失时取消，不回退普通输出。
7. 锁播放器零音量循环等待路由，核验实际路由后定位到开头；定位完成再核验后放音。路由/定位期限为 1.5 秒。内置锁音频短，不能先正常播放再等待核验。
8. prepared、routing、seek 回调有播放器身份检查，失效请求不能借旧回调复活。路由匹配仍不是物理车外发声证明，也不能承诺厂商路由切换期间绝无瞬时泄漏。

## 日志与诊断现状

- 精确过滤已知噪声主题，不整类屏蔽 BodyInfo、DMS、Lock 等。已有精确规则绑定的噪声样本保留。
- 属性枚举单独去重保存，原始 JSON/数组保留完整嵌套值。
- schemaVersion 2 保留兼容字段，增加信号变化历史、关键事件历史、过滤/淘汰计数、属性目录、音频设备及锁配置。
- 内存上限：实时日志 600、候选 180、每候选不同值 12、标记 60、信号变化 1200、关键离散事件 400、属性目录 2048。关键事件历史是观测历史，不是播放历史。
- 0.2.1 增加配置就绪状态、锁触发原因、实际音源/开关/音量，以及自动请求、试听、放音和失败记录。
- 关键持久诊断包含系统启动计数、进程随机标识、PID、服务会话 ID、系统挂起计时差、屏幕/用户事件和日志请求生命周期。异步写入不保证突然断电前最后一条必然保存，未记录销毁也不能单独证明被杀。
- 完整信号历史仍不跨进程保存；读取权限快照不代表系统已经批准本次读取；启动读取但尚未收到日志时不显示为已成功监听。
- 新日志有 `propertyCatalogDropped` 4630，以及大量反复失败的属性候选。目录/候选的去重及失败采样仍有优化空间，当前没有声称已经消除这些噪声。
- 0.2.2 不再对任意日志正文检查权限拒绝文字；stdout 是数据，stderr 单独限量记录。真正 EOF/异常只记录并等待手动重连，避免 5 秒自动请求风暴。标准/扩展共用进程、规则改变保留日志连接；车辆来源局部重置不影响日志基线。
- 0.2.2 保留与当前新事件无关的短音效，关闭/静音/缺文件等不先抢占短音；挡位不可用/离开 R 仍取消驾驶循环与过期挡位队列。显式操作、新可播放高优先级事件和真实焦点丢失仍可中断，不等同于完全禁止音效抢占。
- 0.2.2 在读线程先滤噪声，新增 `logQueueDropped`；宽范围日志读取仍有成本、主线程队列上限 128，不能承诺完全无丢样。

- 未固化中控锁 0/1 含义；UI 的音源选择和车外设备确认不能替代状态校准。
