# 0.3.30：ICC接口与用户授权日志

更新：2026-11-01。本文描述当前运行方式，替代旧版互斥选择ICC、logcat、文件、Carota的方案。

## 固定分工

| 来源 | 状态 | 启用条件 |
| --- | --- | --- |
| ICC本地接口 | 挡位、车速(km/h)、手刹/EPB、电源、充电、默认中控锁 | 打开应用自动监听，无需日志/存储权限 |
| 用户授权实时logcat | 四门、尾门、AutoHold及显式选择的锁事件 | 用户在来源设置中确认启用，并自行完成系统日志授权 |

ICC固定使用已有只读查询，完成后等待250ms，设置中可改500/1000ms；保持串行，0.3.30起失败不再停止监听，按1/2/4/8/10秒退避持续自动重试，成功后恢复所选间隔。失败立即清除ICC状态与触发基线，恢复首样本静默；停止监听、替换ICC来源/改间隔、服务销毁关闭旧请求并取消旧重试。不自动改用其他来源，也不重新申请日志授权。本车实测车速原值即km/h；成功回复且挡位有效时，省略车速按本车静止0显示，失败/未知挡位不补0。手刹不是AutoHold，AutoHold默认1=释放保持、2=正在保持，不代表P挡或一定移动。不驱动持续循环音。中控锁默认按ICC协议启用，不需要二次确认；充电仍需用户核对确认并打开音效开关。

系统挂起期间不能执行请求；恢复调度后继续串行查询与自动重连。没有新增唤醒锁或强行阻止整机休眠，也不能保证被系统杀进程后无缝运行。用户手动停止后，本服务不自行重新开启；仍保留之前明确要求的“再次打开应用自动监听”行为。

## P挡锁声与原厂车外通道

先有新鲜ICC P挡（5秒内）及锁状态基线，再收到锁变化才自动播音。刚进入P挡同批返回的锁变化、首样本、来源恢复、行车及未知/过期挡位都不播音；离开P挡清除待播并停止正在播放的自动锁声，回到P挡不补播。播放器准备完成、路由回调、放音前都复查P挡。手动试听可绕过P挡条件，但不能绕过车外路由约束。

自动匹配 `TYPE_BUS` 输出 `BUS2007_VENDOR_CONTEXT2`，不依赖历史手选设备ID或人工确认；播放器和焦点使用原厂车外声音App已知的 `usage=2007`、内容类型MUSIC。usage不受支持、焦点拒绝、目标不可用或路由不匹配均停止，不回退车内。保留静音建路由、定位到开头再放音及播放中复查。

一次性迁移将锁声开启并把播放器增益由旧默认65%设为100%，保留私有音源；之后保留用户自设开关/音量。音量沿用原厂usage2007组的当前系统值，不写全局音量或 `outside_mode`，没有硬编码尚未证实的原厂数值。MediaPlayer并不等于原厂AudioTrack实现，实际音量与车外功放仍待实车确认。

日志默认关闭，不继承旧版文件或Carota选择，也不把READ_LOGS已授予等同于用户同意启用本功能。新开关保存为`log.enabled`；打开开关但未开始监听时只保存设置，不启动读取。用户已确认启用后，后续开始监听才发起日志请求。系统可能另行确认；本应用不自行授予权限，不绕过确认，读取结束后不自动反复请求。

两类独立运行。日志侧的挡位、车速等接口字段不进入正式状态和音效管线，即使ICC失败也不补位。锁是唯一可手动选择来源的字段：解闭锁设置→锁事件来源，默认ICC，可明确改为授权日志；选择不等于启用或授权日志。日志锁使用独立的旧锁校准，未校准不触发，禁止直接套用ICC的1/2。选中日志时ICC锁仅写对照记录，不覆盖状态或重复播音。切换来源取消锁声并重建静默基线，两种来源均保留新鲜ICC P挡条件。关闭日志仅清除日志基线，不断开ICC；改变ICC间隔仅重启接口，不重新申请日志。停止总监听关闭两类来源；主动重新连接重建两类各自的静默基线。

最新`ES-检测-20261101-184922.json`已有4次ICC锁事件通过P挡保护，但系统拒绝音频焦点；这些调用不是锁事件未到，日志来源也走相同播放链。0.3.30新增`lockAudioFocus`的返回值、时间、usage和gain，拒绝时更新当前输出状态并取消，不强播、不回退、不延后补播旧锁声；未擅改原厂usage2007或焦点策略。尚不知系统拒绝原因、各调用对应车内/车外动作及物理扬声器状态，不能保证已解决。不能长期缓存P挡放行；仍需正常P挡停车→下车锁车→等待→解锁后导出，不清空、强退或重连。

日志事件仍须符合已知协议、时间窗、顺序和校准；首样本、重连、失效恢复、校准期间都不播音，过期排队或积压不补播。授权分组不等于已证明目标车辆全部四门事件存在，仍需安全驻车逐项验证。

## 界面与清理

- 顶部只保留音效设置、车辆检测；首页和状态大屏明确区分接口与日志。
- 0.3.26起配色跟随系统深色模式，覆盖主页、大屏、音频设置/校准弹窗、下拉列表和ADB页；仅调整UI，不改变来源与触发逻辑。
- 0.3.29将0.3.28的候选换算替换为本车已核对的原值km/h与省略字段说明；失效/过期不显示为当前数值，不接入音效。
- 移除全屏显示、分屏探测按钮及分屏探测Activity注册；历史研究类不再作为可启动页面。
- 每次打开应用（包括从后台返回主界面）自动开始车辆监听；手动停止只影响本次，重新打开应用再次监听。日志是否参与仍由用户独立授权开关决定，不因自动监听而默认打开。
- 删除规则管理页面与运行时规则执行；旧规则/自定义音源不主动删除，避免损失已有私有音频，但不再自动运行或出现在规则界面。
- 监听服务不再持有Mega、标准Car、消息总线或讯飞读取器，也不再选择文件、Carota来源。
- 删除独立ICC限时检测、Hub定位、ADB原生重试和消息总线定位入口；通用ADB诊断/APK提取保留。
- 清除无效车辆权限、存储读取权限和可选android.car库声明。历史研究代码和记录保留，不由正式监听服务启动。
- ES预设界面只提供日志门/尾门映射；ICC挡位与其他接口字段不受日志映射覆盖。

## 导出与验证

导出`eventBackend`为`icc`或`icc+authorized-log`，包含`authorizedLogEnabled`与按选择生成的`sourcePolicy`、`lockTriggerSource`；不再导出规则列表。旧探针/文件字段仅保留历史诊断数据兼容，不代表本轮启动读取。

0.3.30的`iccVehicleSource`新增`automaticRetry`、`failures`、`consecutiveFailures`、`recoveries`、`lastErrorCode/At`、`lastSuccessAt`及重试等待/下次时间；等待阶段为`retry-wait`，`active=true`表示仍在监听，不表示接口当前可用。重要失败/恢复写入有界会话记录；最近快照仍限30条。错误只保留分类，不保存Seed、VIN或网络错误正文。检测JSON版本号修正为0.3.30，不再误报0.3.23。

自动化测试使用模拟接口与日志，覆盖来源互斥字段、并行状态、独立开关、授权确认、失效清理、时间/队列保护、静默基线、校准和音频安全。测试通过不等于车辆端已验证日志覆盖、延迟或系统授权弹窗行为。

实车建议：覆盖安装，不卸载；先仅开ICC确认原有功能，再自愿启用日志并授权，驻车开关门对照。无变化或报错仍导出，未收到不当作关闭。
