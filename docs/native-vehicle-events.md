# 0.3.0 原生车辆事件接入

本轮按用户要求，将门、挡位、中控锁、AutoHold音效改为Mega属性直接订阅。版本0.3.0 / versionCode 6；仅更新源码并本地验证，正式包仍由用户在原0.2.x签名环境构建。

## 当前链路

```text
MegaCar.createCar(context, ioHandler, 0, lifecycle)
  → getCarManager("property")
  → mega.car.hardware.property.CarPropertyManager
  → registerCallback(callback, SparseArray<单个ID, 0f>)
  → onChangeEvent(CarPropertyValue)
  → 原始样本诊断 / Protocol.property
  → 锁及AutoHold校准 / TransitionGate
  → SoundEngine
```

没有调用setProperty、车辆控制广播、工程模式开关或厂商音频模式。车外播放继续沿用已选择并人工确认的独立路由，本次没有接入usage2007或outside_mode。

不再自动选择Desay、Android CarProperty或logcat。Mega不可用就展示失败，内置音效不会偷偷改用其他来源。检测页可手动开启日志辅助采集；该开关不跨服务恢复，全部日志样本只作观测，不进入音效或自定义规则。

已有音源、组开关、音量、锁/AutoHold校准和车外设备设置保留。旧日志/Desay/Android规则仍保存，但暂停执行，规则页显示迁移提示；从Mega原生候选重新确认并绑定，避免把不同来源的枚举直接迁移。

## SDK加载和权限

先查应用/系统共享类加载器；随后尝试车机已安装的 `com.mega.car`、`com.iflytek.autofly.carcontroladapter` 的base APK、全部split及声明的共享库。未把提取的厂商DEX或完整SDK复制进项目。文件不可读、类缺失、依赖缺失分别保留错误，不把它们都叫权限拒绝。

读取与订阅始终用本应用UID。读取其他APK中的SDK不会继承其平台签名、系统UID或车辆权限。当前Manifest声明：

| 属性 | ID | 常规区域/类型 | 权限域 |
| --- | --- | --- | --- |
| 四门 | `0x0600002c`～`0x0600002f` | 0或对应门区域 / Integer | ENTRY_LOCK |
| 尾门 | `0x06000031` | SDK返回区域，缺项时0 / Integer | ENTRY_LOCK |
| 挡位 | `0x0400000a` | 0 / Integer | CAR_DRIVING |
| 中控锁 | `0x67000096` | 0 / Integer | VEHICLE_CONTROL |
| AutoHold | `0x50000022` | 0 / Integer | SEQUOIA |
| 车速 | `0x0400000b` | SDK返回区域，缺项时0 / Float | CAR_DRIVING |

完整权限前缀为 `mega.car.permission.`。服务端仍可能拒绝普通侧载应用；声明权限、READ_LOGS和开启ADB都不能代替实际授权。不包含root、Shizuku桥或权限绕过。

优先使用服务返回的区域和类型。目录失败或只返回部分属性时，对表内缺项逐项尝试已确认的区域0；不把一个权限域的失败扩大成全部失败。旧聚合门属性 `100663305` 仅在目录存在时接入，保留80ms多门同值静默保护。

## 订阅、初值与错误

- 每个ID独立调用注册接口，隔离权限失败；失败时清理SDK已添加的本地监听条目，后续显式重试才能真正重新请求服务。
- 关闭SDK的 `isSticky()`：该SDK的sticky实现会在异步任务读取注解默认区域，遇到权限异常可能逃离注册调用栈。应用改为注册后显式逐项读初值并处理异常。
- 注册成功的离散属性由回调驱动，不每3秒用快照覆盖。未注册的属性每3秒只读轮询，检测页标明失败；轮询不能保证捕获快速R→D等中间状态。重新连接或更新检测/规则时可重试注册。
- 接口注册成功不等于服务已经分发、值有效或有权限。需要检查回调次数和有效状态随实车变化。
- 首个有效样本、重连/失效恢复后的首样本只建基线；重复值不重复播报。错误回调和读取失败产生对应属性的不可用样本，取消锁/AutoHold旧请求及失效驾驶循环。
- 按ID和区域丢弃倒序时间戳；离散状态不拿SDK时间戳与Android纳秒时钟相减。断线/关闭后的旧回调由连接及订阅代次过滤，重新建立连接先清基线再采样。
- 扩展检测及规则修改只增减所需属性，不重新建立既有基线。取消订阅接口不可用时保留错误；退出检测不依赖重连来清除核心状态。

Mega车速仅在原时间戳与SDK便利构造器的uptime毫秒约定一致、且5秒内新鲜时可用；零时间戳、其他单位或未知时钟保持不可用。实际服务端是否遵循此约定仍需实车核对，不能宣称已修好车速或已支持声浪。导出同时记录原始时间戳、接收uptime毫秒和elapsed纳秒，供确定服务端约定。

## 挡位与状态校准

同一属性的SDK常量与实车日志存在冲突，不自动根据一个值猜车型：

| 检测页选择 | P | R | N | D | M/S |
| --- | --- | --- | --- | --- | --- |
| ES已观测（默认） | 1 | 2 | 3 | 4 | 未预设 |
| SDK定义（手动选择） | 0 | 1 | 2 | 3 | 4 |

两套均保留已知扩展值101/102/103或300/113对应P/R/N/D。ES默认中的0不当P或N，未知、非Integer、非全局区域及不可用状态不触发。SDK的4实际常量名SPORT，当前兼容既有M音源槽位，因此界面标M/S，不宣称实车具有独立S挡事件。

先在检测页对照实际挡位、原始值与解码结果，再启用挡位/倒车音效。更换编码会重新连接并静默建立基线。锁的两个整数和AutoHold的1/2方向仍必须按实车操作校准；没有固化0/1闭锁方向或1/2保持方向。

新的可播放挡位变化继续立即取消旧挡位短音与倒车循环，旧prepare回调不能复活旧R。锁的自动音效仍需要独立车外输出人工确认，不能用门事件代替锁事件。

## 检测与导出

检测页的“原生订阅检测”展示SDK来源、实际管理器、逐属性注册结果、回调/读取次数、最新status/raw和异常。候选、已知状态、操作标记及变化历史继续保留。注册条目的区域-1仅是诊断汇总标记，不向车辆服务请求该区域。

导出新增：

- `eventBackend`：`Mega native property subscription`。
- `diagnosticLogs`：本次是否手动开启辅助采集。
- `megaGearEncoding`：`es-observed`或`sdk`。
- `nativeSdkStatus`、`nativeManagerStatus`。
- `nativeSubscriptions`：注册、错误、回调/读取计数、原始时间戳及对照时钟；注册成功也需结合断线标记判断。

历史schemaVersion 2和已有字段保留。SDK加载失败时可导出实时诊断的完整异常；不提交用户完整检测文件或车辆日志。

## 本地验证与实车验收

本地通过145项核心检查、70项Android/Robolectric测试和资源/Java/DEX编译。新增测试用独立的手写测试SDK接口模拟已核对的反射签名，未复制厂商实现；这些测试类只编译到测试输出，不进入应用DEX。

覆盖部分/拒绝的属性目录、逐权限域注册失败及清理重试、正确区域、锁/AutoHold映射、同步生命周期回调、旧回调失效、错误恢复、扩展检测保留基线、uptime车速及导出。音效测试覆盖原生回调贯穿到播放器的快速R→D、取消旧prepare、日志无法覆盖原生状态、静默首样本及锁独立路由。

在原签名环境执行：

```sh
python3 tools/build.py
```

仅编译验证、不签名：

```sh
python3 tools/build.py --compile-only
python3 tools/ui_check.py
```

车机下一轮：

1. 安装0.3.0，暂时关闭音效组、保持日志辅助关闭；确认SDK与管理器能加载，四类属性有有效原始变化及回调。
2. 对照P/R/N/D选择编码；核对门/尾门，校准中控锁及AutoHold后再开启音效。
3. 测试快速R→D、保持→释放、重复状态、重新连接与恢复；确认旧声音取消、首样本不补播，切换扩展检测不丢既有基线。
4. 按操作时间标记并导出；被拒绝时提供原生逐项错误，不能用日志权限截图认定车辆接口已授权。
5. 车外扬声器、后台存活、锁车休眠、真实回调延迟及实际功放仍需实测，本地测试不能证明。
