# 0.3.6 讯飞挡位只读检测

版本：0.3.6 / versionCode 12。依据[平台服务实码复核](platform-service-investigation-20261031.md)实现独立、手动、有界的检测；不改变Mega音效后端，不借shell身份读取，不增加车辆控制或写权限。

## 使用

1. 覆盖安装同签名的新APK，不先卸载旧版。车辆安全停稳后进入“车辆检测”。
2. 找到“讯飞挡位 · 只读验证”，点击“开始讯飞挡位检测”。阅读首次绑定可能唤起原厂模块、更新内部导航标识的提示，确认后开始。不自动读取VIN，不调用控制方法。
3. 查看注册返回码、查询原始值、ready次数、挡位回调次数和变化次数。无需开启主音效监听、扩展扫描、日志权限或ADB，也无需专门切挡或行驶。60秒内自动结束；点击停止、离开检测页或App进入后台也会注销解绑。
4. 结束后确认注销结果，再点“导出记录”，提供`ES-检测-*.json`。若同时需要ADB元数据，可结束后进入“ADB 只读诊断”，取消重复APK提取及已知失败的Mega probe再采集；ADB JSON同样附带最后一次App讯飞检测快照。二者时间独立，不能称为同次shell验证。

## 实现边界

- 读取`ro.autofly.service.system`；明确读到空值时才使用已研究的默认包，属性读取失败不盲猜宿主。解析该包的精确服务组件，验证启用、导出、系统包及入口权限后才绑定。
- 验证Binder描述符；只发送消费端注册8、查询12（固定键gear）和注销9。先注册再查初值，避免注册间隙漏掉回调；不用整套厂商SDK，不注册为Custom数据提供者。
- 使用独立后台串行线程执行同步Binder调用，UI不等待远端返回。绑定/操作约8秒无进展即标记超时并解绑，监听阶段45秒，总会话最多60秒。Binder同步调用无法强行取消；如已卡住，注销只能待调用返回后继续。全局只允许一个未完成会话，卡住时不堆积新的调用或后台线程，也不伪称注销成功。
- 回调只接受解析得到的服务UID和指定协议；兼容ready、unique-code-ready、error/progress、car-config及vehicle-state通知。只统计gear的有效枚举变化，首个有效回调建基线；其他通知不是挡位。未知编码会打断变化基线。
- callback队列最多64条，事件历史最多120条，记录丢弃数；断连不自动重连，停止后忽略迟到回调。新会话不被旧会话的延迟清理结果覆盖。
- 查询结果单独标记`readMayBeCached=true`；回调没有源时间戳，`callbackReceivedAt`仅是本App接收时间。1001保持GEAR_NONE，不擅自解释成N挡。没有将任何结果自动标为“已验证实时挡位”。
- 数据只进入独立诊断快照/日志，不传给`MonitorService.accept`、音效状态、候选绑定或规则引擎；不会因检测回调播放挂挡音或倒车循环。

## 导出

`platformVehicleProbe`记录会话ID、App UID、服务UID、真实宿主/版本/组件、绑定、读取、注册、ready、回调、变化、超时、注销和错误。`registered`表示当前状态，停止后为false；历史是否成功看`registerResult`。注册成功但无callback不算数据验证；一次返回1002也可能是旧缓存。门、锁和AutoHold不在本轮验证范围。

最后一次快照保存在App私有设置中，检测导出与ADB导出都携带它；App恢复时将遗留active会话标为中断、清理结果未知。没有宣称本地模拟测试等于实车通过，实车UID访问和有效数据仍以导出结果为准。

## 本地验证

145项核心检查、154项Android/Robolectric测试通过（含28项讯飞检测专项测试），覆盖注册/读取/注销的交易白名单、ready与变化基线、缓存标记、调用者UID、权限拒绝、路由失败、超时、断连、迟到回调、队列上限、旧会话隔离、持久化和两类诊断导出。界面截图已检查，APK签名及对齐通过；证书与0.3.5一致，可对同签名安装包覆盖升级。
